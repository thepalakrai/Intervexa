# Virexa AI — Backend (Day 1 skeleton)

## Setup

```bash
# 1. Create and activate a virtual environment
python -m venv venv
source venv/bin/activate      # on Windows: venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Copy the env template and fill in your real Azure credentials
cp .env.example .env
# then edit .env with the values you saved earlier:
#   - Foundry API key + endpoint
#   - Blob Storage connection string
#   - Cosmos DB endpoint + key
```

## Run it

```bash
python main.py
```

The API will be live at `http://localhost:8000`.
Interactive docs (auto-generated by FastAPI) at `http://localhost:8000/docs` —
use this to test file uploads without building any frontend yet.

## What's wired up so far (Day 1)

- `POST /upload-resume` — accepts a PDF, uploads it to the `resumes` Blob container,
  extracts plain text, returns a candidate_id + text preview.
- `POST /upload-jd` — same, but for the `job-descriptions` container.
- `services/foundry.py` — ready to call your `virexa-model` deployment, includes
  a stub `analyze_profile()` function for Day 2 (resume + JD → skill gap JSON).

## What's wired up now (Day 2)

- `POST /start-interview` — takes resume_text + jd_text (use the text_preview
  from your Day 1 upload responses, or the full extracted text), analyzes the
  profile via Foundry, creates a Cosmos session, returns an opening question.
- `POST /answer` — takes a question + the candidate's answer, evaluates it via
  Foundry (structured JSON scores), adjusts difficulty up/down, generates the
  next question. Returns `status: "completed"` once 8 questions are answered.
- `GET /final-report/{candidate_id}/{session_id}` — aggregate readiness score,
  skill gaps, and the full question/answer/evaluation history.
- `agents/interviewer.py` — generates one question at a time based on profile,
  history, and target difficulty.
- `agents/evaluator.py` — scores each answer on 5 dimensions + a decision
  (increase/decrease/same/follow_up).
- `agents/planner.py` — rule-based difficulty adjustment on top of the
  evaluator's decision. `TOTAL_QUESTIONS` (currently 8) controls interview length.

## Testing the full loop right now (no frontend needed)

1. Run the server (`python main.py`)
2. Open `http://localhost:8000/docs`
3. `POST /upload-resume` with a real PDF → copy the `candidate_id` and
   `resume_text_preview` from the response
4. `POST /upload-jd` the same way (pass the same `candidate_id` as a query param)
5. `POST /start-interview` with:
   ```json
   {
     "candidate_id": "<the id from step 3>",
     "resume_text": "<paste the resume preview text, or better: your own full text>",
     "jd_text": "<paste the jd preview text>"
   }
   ```
   Copy the returned `session_id` and the opening `question`.
6. `POST /answer` with the question + a typed answer (try one strong answer and
   one weak answer across a few calls, and watch `current_difficulty`/next
   question topic change in response — that's your adaptive engine working)
7. After a few rounds, once you get `"status": "completed"`, call
   `GET /final-report/{candidate_id}/{session_id}` to see the aggregate report.

**Note on step 3-4 text**: the `text_preview` from Day 1 is capped at 500
characters for a quick sanity check. For real testing, it's worth extracting
the full text yourself (or extending `/upload-resume` to return full text)
so the profile analysis has enough to work with.
